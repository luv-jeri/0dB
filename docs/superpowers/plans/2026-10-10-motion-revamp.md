## 2. Technique map

### Rules shared by every row

The table codes below are implementation requirements, not optional shorthand.

- **S** means static and complete under reduced motion, forced colours, failed enhancement or no script. All meaningful text is available in document order. A multi-scene scrub becomes a normal stack, not one frozen scene. Forced colours use CanvasText and existing system focus treatment.
- **R** means mirror spatial inline coordinates, wipe direction and visual stagger from inline start in RTL. Never reverse a string or mirror glyphs. Block-axis travel stays vertical. Mixed-script runs retain native shaping. A script that cannot be positioned faithfully gets its whole native line or S.
- **V** means a native CSS view or scroll timeline with explicit ranges and linear scrubbing, enabled only for a verified compositor path. Otherwise S. No decorative scroll listener, scroll-time React update or rAF fallback. **Q** is the sole exception, TypeSequence's bounded JS fallback, specified below. Owner decision f assumes this split.
- **E** means a single entrance after a person scrolls an initially offscreen subject into view. IO arms it and CSS performs its short response, then restores plain content. Initially visible content stays complete. This is an action response, not an ambient loop. Scrub mode instead uses V and remains reversible.
- **P0** means no Pretext needed. **PL** means `prepareWithSegments(text, font, options)` then `layoutWithLines(prepared, width, lineHeight)` before motion. **PC** means Calligram's `prepareWithSegments` then `layoutNextLine(prepared, cursor, chordWidth)` for each row, advancing to `line.end`. **PW** adds `measureNaturalWidth` for intact runs. These are real 0.0.9 exports, not a shape API. Prepared types begin at `P/dist/layout.d.ts:18-24`, cursors at `:25-28` and functions at `:62-73`.
- D4 permits transform, opacity, clip-path and font axes while scrolling. This implementation uses transform and opacity first. Clip-path requires compositor evidence, otherwise the effect stays static. No scroll-time font-axis animation is scheduled, since support alone does not establish its cost. No width, height, inset, tracking, layout or text replacement. Native CSS and Q never own the same effect together.
- Phones get no parallax. In this plan that means viewport width at or below 860px **or** a coarse primary pointer. A desktop with a narrow component also gets a static layout when the component cannot reserve travel room.

Each image replacement below is a **word-shape**. Its outline is implied by readable words. There is no visible path, filled silhouette, image mask or glyph converted to particles. A circle can be the “0” made of the library's own description. A wave can be prose about reading rhythm. A photograph of a client project would become that project's actual account set in words, not the word “photo” repeated as texture.

Do not assume that a child Calligram already provides a visibly complete failed-layout state. Its unprepared text sits in a shape-sized box with overflow hidden (`registry/0db/styles/calligram.css:10-14`). A composition using that child must also provide its complete native prose outside the crop. Keep that prose visible when script, fonts or preparation fail. Screen-reader-only text does not satisfy this visual fallback. Each affected item supplies this at its composition boundary.

### Stored poses and drawing

TypeSequence stores text once and geometry separately. An authored scene has a stable source string, line/run identifiers, three endpoint layouts and two transitions. The text dictionary is plain strings. The client compiles **five stops per run by default, at most nine across the whole two-transition sequence**, with **128 runs per scene**. These are total stops, not nine per chapter. Each pose holds only numeric transforms, opacity and fixed clip parameters. A run's width, font and DOM identity stay fixed while scrolling.

Use one shared midpoint for the circle and include both outer endpoints. Five stops give 640 run-stop records at 128 runs. The hard ceiling is 1152 records, with the shared midpoint stored only once. This replaces the prior draft’s 33 × 2 × 128, or 8448, potential run-stop records. Prefer intact words for simple scripts and intact shaped runs for other scripts. If a legible circle cannot fit within the limits, use fewer, larger runs or a static paragraph. Do not shrink text below 16px to force a silhouette. The native renderer installs scoped CSS keyframes once after compilation and attaches them to the section's timeline. Q interpolates the same neighboring poses and writes to the same preallocated nodes. No frame allocates a new span or sets a new string.

This carries the video's pre-render lesson without shipping raster frames. There are no WebP sequences, video elements, per-frame canvas text measurements or generated image assets. Optional number readings are updated only at meaningful endpoints, not announced every frame.

Use a semantic source block as the reading and copy source. The visual arrangement is aria-hidden and has no focusable descendants. While enhanced, the semantic block can be visually hidden only if all of its words are also legible in the static fallback and the layout has reserved room. Selection or focus in the text region exposes the native paragraph. The final state hands back to native text at matching geometry. Invalid preparation leaves native prose visible.

### Chaining

Chapter A’s final pose and chapter B’s initial pose reference the **same pose object**, counted once in the nine-stop limit. Match source identity, run order, font key, bounds, direction, transform, opacity and clipping. A resize rebuilds both chapters together. Reject a chain whose shared pose differs.

Keep one stage across the two chapters. The progress intervals touch without an overlap or gap. The calligram therefore stays in place as the first chapter ends and the second begins. At the final endpoint, the visible native paragraph occupies the same reserved box. No absolute positioning between unrelated page sections and no matching by eye. Direct navigation into or past the scene calculates the correct state immediately.
