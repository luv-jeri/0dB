# 0dB Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the Fermata specimen into 0dB, a shadcn registry of 67 items with a self-built docs site, checked and deployed to 0db.cojeev.com.

**Architecture:**
- Each item is one TSX file and one CSS sidecar, lifted from its `fermata.css` fence.
- A build script turns `content/*.ts` and `registry/0db/**` into `registry.json` and `public/r/*.json`.
- A Next 16 static export renders the docs from the same items, `examples/*.tsx` and DESIGN.md.

**Tech stack:**
- Next 16, React 19, TypeScript 5.9, Tailwind v4
- Radix (slot, popover, tooltip, hover-card, dropdown-menu, context-menu, menubar, navigation-menu, tabs, toggle, toggle-group, dialog), cmdk
- clsx, tailwind-merge, sugar-high, marked, lenis, @chenglou/pretext
- shadcn CLI, Playwright, Node 22

**Spec:** `docs/superpowers/specs/2026-09-30-0db-library-design.md`

Following the owner's override, this plan holds interfaces, invariants as named tests, destructive-step ordering and failure rules. It contains no function bodies.

## Global Constraints

- Tokens are `--db-*`; classes are `db-<name>`; keyframes are `db-*`. Nothing named `f-` or `--f-` may remain in `registry/`, `app/`, `components/`, `examples/` or `content/`.
- Variants use `data-variant` and `data-size`. No cva.
- React 19: a ref is a plain prop, there's no `forwardRef`, and `"use client"` appears only where hooks or Radix need it.
- Every item has `data-slot` on its root and parts, and `className` is merged with `cn`.
- Ours in roman, yours in italic. One accent per view. Nothing moves unless the person acts, and reduced motion makes everything instant. No icons, cards or shadows.
- Sidecars are wrapped in `@layer components`, and base.css in `@layer base`.
- `!important` is allowed only on `[hidden]` and `.db-sr` in base.css.
- Registry imports `@/registry/0db/ui/x` are rewritten to `@/components/ui/x`, and `@/registry/0db/lib/utils` to `@/lib/utils`.
- The base URL is `https://0db.cojeev.com`, and `DB_REGISTRY_URL` overrides it.
- Copy is in sentence case, with active verbs. An action keeps its name ("Copy" becomes "Copied"). Errors say what to fix and never apologise.
- The source of truth for each item's look and behaviour is `specimen/fermata.css` (its fence), `specimen/index.html` (markup and script) and the DESIGN.md contract.

## Review Focus

1. **A consumer app with Tailwind preflight.** 0dB's look must still hold. `check:install` asserts the computed styles of a statement button and a checked checkbox in the fresh app (Task 11).
2. **A consumer imports an item in a Server Component.** Items with hooks must carry `"use client"`. The install app's page is a Server Component that renders every example (Task 11).
3. **Right-to-left pages.** `check:pages` loads `/docs/slider/` with `dir="rtl"` and asserts there's no sideways overflow (Task 11).
4. **Reduced motion.** `check:pages` emulates `prefers-reduced-motion` and asserts that `--db-andante` resolves to `1ms` (Task 11).
5. **Theme restored before paint.** A stored Nocturne choice must not flash Day. `check:pages` sets localStorage, reloads, and reads `data-mode` in the first document state (Task 11).

### Task 2: Registry build

**Files:** `scripts/build-registry.mjs`, `scripts/lib/items.mjs`, `content/types.ts`, and the test `tests/registry.test.mjs`.

**Interfaces:**
- `content/types.ts` exports:
  - `type ComponentMeta = { name: string; title: string; movement: "II"|"IV"|"VI"|"VII"|"VIII"|"IX"|"X"|"XI"; contract: string; summary: string; underneath: "native"|"hook"|"radix"|"cmdk"; props: { name: string; type: string; default?: string; description: string }[] }`
  - `defineComponent(meta: ComponentMeta): ComponentMeta`
- `scripts/lib/items.mjs` exports:
  - `readItems(root): Promise<Item[]>`, reading `content/*.ts` through `tsx`
  - `deriveDeps(source: string): { npm: string[]; siblings: string[] }`
  - `rewriteImports(source: string): string`
- `node scripts/build-registry.mjs [--check]`:
  - It writes `registry.json` and runs `shadcn build -o public/r`. It then post-processes each payload's file contents with `rewriteImports`, and copies `public/r/registry.json`.
  - `--check` rebuilds into a temporary folder and exits 1 on any difference.

**Named invariant tests** (`node --test`):
- `rewrites registry imports to consumer aliases`
- `derives npm dependencies from bare imports and siblings from ./ and @/registry imports`
- `every component item installs its sidecar through a css @import`
- `base item exposes theme variables for Tailwind`
- `registry:check detects a stale payload`

- [ ] Write the tests first. They fail because there's no module yet. Then implement until they pass.
- [ ] Commit.

### Task 3: Reference items (the template for every builder)

These are button, checkbox, tooltip, dialog, source and steps. Each one covers a different kind of underneath: native, native plus hook, Radix, and new.

**Files, for each item:**
- `registry/0db/ui/<item>.tsx`
- `registry/0db/styles/<item>.css`
- `content/<item>.ts`
- `examples/<item>.tsx`

**Interfaces, produced** (these are the conventions every later item follows):
- Examples use `export default function Example()`, and optionally `export function States()`, which pins states with `data-force`.
- An item may borrow another item's classes only if that item is imported or listed in the meta.
- `Source({ code, lang = "tsx", title? })` is a Server Component. It renders highlighted HTML with sugar-high, maps the token classes to the 0dB rules, and includes a client `CopyButton`.
- `Steps` / `Step` render as `<ol class="db-steps">`.

### Tasks 4 to 9: Porting items (parallel builders in two waves, with no overlap in the files they touch)

Every builder works to these rules:
- It follows Task 3's files and conventions exactly.
- It reads its fence (from the line map in the builder brief), the specimen markup and script, and the DESIGN.md contract before writing.
- It creates only its own items' four files. It never edits shared files.
- After each item, it runs `npx tsc --noEmit` and `node scripts/build-registry.mjs`.
- It doesn't commit; the coordinator commits after each wave.

**Wave A** (these depend only on the base and Task 3):
- **Task 4:** link, kbd, fraction, meta, corners, spinner, radio-group, dial, picks, switch, slider
- **Task 5:** progress, toast, empty, alert, skeleton, badge, note, accordion, collapsible
- **Task 6:** card, popover, calendar, hover-card, sheet, drawer, resizable, scrollbar, scroll-area, aspect-ratio, carousel
- **Task 7:** table, chart, avatar, item, typography, marker, attachment

**Wave B** (these depend on wave A items):
- **Task 8:**
  - field, select, toggle, toggle-group, button-group, input-group, input-otp, form
  - combobox, which needs popover
  - date-picker, which needs popover and calendar
- **Task 9:**
  - tabs, rows, pagination, breadcrumb, navigation-menu, command (with CommandDialog)
  - dropdown-menu, context-menu and menubar, which need popover
  - sidebar, which needs sheet
- **Task 9b:**
  - message, which needs avatar and badge
  - thread, which needs message and scrollbar
  - questionnaire, which needs radio-group

The base pieces (link, meta, kbd, corners, fraction) have their CSS in base.css. Any item may therefore use those classes, with only the base as a dependency.

**Pinned interface:** `Scrollbar({ variant?: "inner" | "page", min?: number, sections?: { id: string; num: string; name: string }[] })`. It's placed as a child of any scroll container, which it measures as its host. The page variant measures the document instead.

A builder's report lists, per item: its files, what's underneath, the siblings it depends on, and anything in the specimen it couldn't carry over (with the reason).

### Task 11: The checks

**Named invariants:**

  - `every item has ui, content, example and a DESIGN.md contract`

  - `no f- names remain`

- `check:install` builds a fresh `create-next-app` project with Tailwind:
  - `every item installs`
  - `server page renders every example`
  - `statement button and checked checkbox keep 0dB computed styles`
- `check:pages`:
  - `no console errors on any page at 375 and 1440`
  - `no sideways overflow`
  - `rtl slider page has no overflow`
  - `reduced motion collapses tempo`
  - `stored nocturne applies before paint`
