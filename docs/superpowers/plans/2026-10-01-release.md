# 0dB release: review, production-ready, deploy, publish

Owner, 2026-10-01: "once done please ask Astra in extra high to review the whole code base for the quality and the code quality, ask it to give feedbacks gaps and other things. we need to make it production ready, work with astra to make it production ready and deploy it on 0db.cojeev.com. also follow the same steps as the 000h like publish it everywhere with astra work together. commit each step properly so that we can roll back things if we want to later."

Astra is `gpt-6-astra` in the Codex CLI. "Extra high" is `model_reasoning_effort="xhigh"`. It reviews read-only: `codex exec -m gpt-6-astra -c model_reasoning_effort="xhigh" -s read-only`.

## Order (one commit per step, so each can be rolled back)

1. **Finish the build.** The variants wave, the 000h port (`2026-09-30-variants-wave.md`), the follow-ups pass, the separation pass, and a full `npm run check`. This is commit 1; the wave and the port share DESIGN.md and the generated registry, so they land together.
2. **Astra review.** The whole codebase, for code quality, design-system integrity, accessibility, performance, security headers, registry/install correctness, docs, and gaps against production. Output: `docs/superpowers/reports/2026-10-01-astra-review.md`. This is its own commit.
3. **Fix rounds.** Fix by severity. Astra re-reviews the diff after each round, until it has no blocking findings. One commit per round.
4. **Production parity with 000h.** One commit per item:
   - security headers and CSP for the static export (000h ships a strict CSP and `frame-ancestors 'none'`)
   - `robots.txt`, `sitemap.xml`, structured data, and an OG image
   - a fresh-consumer install from the built registry (`check:install`)
   - `llms.txt` (000h planned it but never shipped it)
5. **Deploy.** Merge `library` → `main`. CI runs `npm run check`, and then its deploy job runs `wrangler deploy` (`wrangler.jsonc`: Worker `0db`, custom domain `0db.cojeev.com`, static assets from `out/`). This needs the repository secret `CLOUDFLARE_API_TOKEN`. Without it, the first deploy runs locally with the logged-in wrangler. Check the live site afterwards.
6. **Publish, following 000h.** Each of these is outward-facing, so the owner confirms each one before it's sent:
   - GitHub: the repo description, homepage and topics; a `v0.1.0` tag and release.
   - The shadcn registry directory: a PR to shadcn-ui/ui (000h was accepted as `@000h-cojeev`; the draft entry is `docs/directory-entry.json`).
   - registry.directory and awesome-shadcn/ui.
   - Google Search Console: the sitemap. The `cojeev.com` property is already verified for 000h.

npm is not a target: 000h is `private: true`, and installs go through the shadcn registry URLs.
